# perf:worker at e25ec01, 1280x720 viewport, 2026-10-15

**Snapshot of 2026-10-15, not refreshing.** One run of `npm run perf:worker` on commit `e25ec01` (app 2.34.1), frames at a 1280x720 CSS viewport, the reference run for the worker host work (RUN-0a was checked against it). Live numbers come from re-running it. Raw data: [verticopolis-benchmarks](https://github.com/maniator/verticopolis-benchmarks/tree/main/results/2026-10-15-e25ec01c-worker-1280x720) (private repository).

- Machine: owner's PC (Ryzen 5 5600X, RTX 3060 through ANGLE D3D11), Chromium 149, GPU renderer. 10 repetitions of four hosts, 1x and 4x throttle, small, medium and large. Validation passed.

## Top numbers

Bare engine, 720 steps, median [95% interval], TypeScript over WASM:

| Scenario | 1x                                                  | 4x                              |
| -------- | --------------------------------------------------- | ------------------------------- |
| small    | 107 ms against 75.7 ms (1.42x)                      | 602 ms against 341 ms (1.59x)   |
| medium   | 690 ms against 387 ms (1.77x)                       | 3045 ms against 1763 ms (1.74x) |
| large    | 702 [670, 734] ms against 830 [786, 971] ms (0.83x) | 3050 ms against 3632 ms (0.82x) |

Cold start to mode ready at 1x: 485 ms (TypeScript), 606 ms (WASM), 603 ms (WASM worker), inconclusive.

## What it shows

- The bare Rust engine was faster on small and medium and about 20% slower on large at this commit; the large-tower gap closed later (see [2026-10-21-9cd44d1-1051-fresh-large.md](2026-10-21-9cd44d1-1051-fresh-large.md)).
