# perf:worker at e25ec01, 640x360 viewport, 2026-10-15

**Snapshot of 2026-10-15, not refreshing.** One run of `npm run perf:worker` on commit `e25ec01` (app 2.34.1), frames at a 640x360 CSS viewport. Live numbers come from re-running it. Raw data: [verticopolis-benchmarks](https://github.com/maniator/verticopolis-benchmarks/tree/main/results/2026-10-15-e25ec01-worker) (private repository).

- Machine: owner's PC (Ryzen 5 5600X, RTX 3060 through ANGLE D3D11), Chromium 149. 10 repetitions of four hosts, 1x and 4x throttle, small, medium and large scenarios. Validation passed.
- The same commit ran again at 1280x720 the same day; that run is the reference: [2026-10-15-e25ec01c-worker-1280x720.md](2026-10-15-e25ec01c-worker-1280x720.md).

## Top numbers

Bare engine, 720 steps, median [95% interval], TypeScript over WASM:

| Scenario | 1x                                                  | 4x                              |
| -------- | --------------------------------------------------- | ------------------------------- |
| small    | 110 ms against 76.5 ms (1.43x)                      | 621 ms against 337 ms (1.85x)   |
| medium   | 685 ms against 382 ms (1.79x)                       | 3033 ms against 1751 ms (1.74x) |
| large    | 705 [694, 733] ms against 806 [791, 830] ms (0.87x) | 3016 ms against 3653 ms (0.83x) |

Cold start to mode ready at 1x: 521 ms (TypeScript), 594 ms (WASM), 542 ms (WASM worker).

## What it shows

- The viewport changes the frame rows and leaves the bare-engine rows where the 1280x720 run put them: WASM faster on small and medium, about 15% slower on large at this commit.
- The engine package adds about 325 KiB (Brotli) to the download, and the WASM modes start 70 to 120 ms later than TypeScript.
