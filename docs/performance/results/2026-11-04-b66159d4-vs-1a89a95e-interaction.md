# Interaction benchmark, b66159d4 against 1a89a95e

**Snapshot of 2026-11-04, not refreshing.** One run of `npm run perf:interaction` (see [interaction-benchmark.md](../interaction-benchmark.md)); run it again for current figures. It is not a gate. The raw `results.json`, the full `report.md` and the run log are in [verticopolis-benchmarks](https://github.com/maniator/verticopolis-benchmarks/tree/main/results/2026-11-04-b66159d4-vs-1a89a95e-interaction) (private repository), not in this repo.

- Arm A: 2.78.12 at `b66159d4`. Arm B: 2.78.18 at `1a89a95e`, the merge of #1749 (the scene-sync fix). B also carries every other change merged to main between the two commits (2.78.13 to 2.78.18), so a difference is not the fix alone. Both are tooling builds from their own worktrees.
- Large tower (43,358 units), 6 paired repetitions at 1x and 4x CPU throttle, 20 s per phase with one autosave in the middle, a fresh Chrome 156 per arm, arms alternating.
- Machine: Windows PC, Ryzen 5 5600X, RTX 3060 through ANGLE (D3D11), real Chrome 156.0.8078.80 with the CPU throttle applied through the DevTools protocol, High performance power plan.
- Machine state: the Wine harness was idle, idle CPU was about 5 to 12% before the run, and 6 background Chrome processes could not be closed, so the numbers carry a little noise from them. Light git and GitHub work ran in other sessions during the hour.
- All 24 arm runs ran clean: 0 page errors and 0 frame errors, and the build phase placed its offices every time (20 at 1x, 11 at 4x).

## What it shows

The table above has only frame p99 and long tasks for seven of the twelve CPU and phase rows. The points below also cite frame p95, 1% low, input delay and slow clicks and keys for all phases, including idle, zoom and inspect; those figures come from the full report (private, linked at the top).

- Between the two commits the interaction numbers are level. At 1x every phase is the same within noise on frame p95, p99, long tasks and input delay, and slow clicks and keys are identical.
- Intervals that exclude "no change", all small: at 4x B has fewer long-task milliseconds in the inspect phase (-29.2 per second, -43.6 to -5.3), a better 1% low in idle (x1.067, 1.016 to 1.254) and inspect (x1.083, 1.059 to 1.213), and 21.5 ms less input delay to the next frame p99 in pan (-34.4 to -9.0).
- Adverse results, also small: at 4x in the build phase B's frame p95 is 1.1% longer (x1.011, 1.001 to 1.017); at 1x in zoom B's 1% low is lower (x0.971, 0.848 to 0.997) with 0.3 ms more long-task time per second (0.0 to 0.7).
- Not shown: anything about the engine's step cost, startup or memory, or a different tower size.
