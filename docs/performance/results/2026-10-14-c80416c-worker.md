# perf:worker at c80416c, 2026-10-14

**Snapshot of 2026-10-14, not refreshing.** One run of `npm run perf:worker` on commit `c80416c` (app 2.32.0). Live numbers come from re-running it. Raw data: [verticopolis-benchmarks](https://github.com/maniator/verticopolis-benchmarks/tree/main/results/2026-10-14-c80416c-worker) (private repository).

- Machine: cloud container, 4 Xeon CPUs, headless Chromium 141 with the SwiftShader software renderer, so every frame metric is invalid. Timing rows are context only.
- 10 repetitions of four hosts (TypeScript, WASM main thread, WASM frame sync, WASM worker), 1x and 4x throttle, small, medium and large scenarios. Validation passed.

## Top numbers

Bare engine, 720 steps, median, TypeScript over WASM:

| Scenario | 1x                              | 4x                                |
| -------- | ------------------------------- | --------------------------------- |
| small    | 262 ms against 126 ms (2.04x)   | 1315 ms against 756 ms (1.81x)    |
| medium   | 1941 ms against 1031 ms (1.90x) | 11635 ms against 6584 ms (1.71x)  |
| large    | 1985 ms against 2902 ms (0.70x) | 15595 ms against 30179 ms (0.51x) |

Startup: cold start to mode ready was 961 ms (TypeScript) against 977 ms (WASM) at 1x, inconclusive.

## What it shows

- WASM was about twice as fast on small and medium and slower on large on this machine. The 2026-10-15 runs on the owner's PC with a GPU replaced it as the reference. Analysis: [wasm-worker-host.md](../wasm-worker-host.md).
