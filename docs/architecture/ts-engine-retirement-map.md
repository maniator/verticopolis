# Retiring the TypeScript engine's rule suites (#1875)

PR 2 then deleted `src/engine/` itself; what each remaining importer reads or runs now is in [ts-engine-deletion-map.md](./ts-engine-deletion-map.md).

The TypeScript reference engine (`src/engine/`) is being deleted. Each integration suite that tested a rule on it alone was retired with this map: every rule (one row per `describe` block) names the Rust test that now holds it. A `NEW` entry is a test written for the retirement, in `engine-rs/src/rule_tests/<suite>.rs`; every other entry is a test that already covered the rule. Each rule test file opens with the same list for its suite.

A break-check, listed in the notes, means the engine rule was broken on purpose and the named test was seen to fail before the rule was restored.

### Notes

- **A newer save is refused.** The TypeScript loader read a save stamped with a later version than its own; the Rust loader refuses it with `NEWER_SAVE_REFUSAL` (#1603). That is intended, so `rule_tests::save_versions` asserts the refusal.
- **A new game opens with a welcome line** in the Rust log, which the TypeScript engine did not write. `rule_tests::save_log` clears it before each case, so the cases count only the lines they add.
- **Fixture towers build on the port.** `src/tests/fixtures/serviceDiagnostics.fixture.ts` holds self-contained builders over the tooling tower's shape: the integration suite runs them on a port kit draft, and the browser specs (`e2e/serviceDiagnostics.spec.ts`, `e2e/tenantDiagnostics.spec.ts`) run the same source on the page's engine through `buildInPage` in `e2e/helpers.ts`.
- **Comparisons became literals.** The converted conformance and frontend suites compared the Rust answer with the TypeScript one. They now pin the Rust answer as a literal value, or as a value the test derives from the catalog, so each still fails when the rule moves.
- **Rule tests are test code to the guards.** The frame-field and label guards (`engine-rs/src/view/lexer_tests.rs`) skip `src/rule_tests/`, as each rule test seats its rooms by writing their state directly. `rule_tests::attendance` reads the crowd's sources from disk, so `rule_tests/mod.rs` declares it by path, which the independence guard counts as test code. The other files compile their fixtures in with `include_str!`.
- **Break-checks:** `diagnostics_towers` (the hold tax rounded down), `undo_signature` (No Rate left out of the fingerprint), `heatmap` (the ramp exponent set to 1), `event_fx`, `save_log` (the surrogate pop removed), `housekeeping_legibility` (the floor list formatting), `save_hardening` (the weather roll), `save_versions` (the founder cutoff), and the earlier `calendar`, `attendance`, `capacity`, `infestation`, `demand_pools`, `commute` and `condos` files, each noted in its row.

- **Rust difference, W3 party hall.** The TS test compared a hall's floor-2 vs floor-8 takings gap against fast food's. In Rust the hall's takings follow its audience, which the floor moves too (gap 1682 vs fast food 313 on the TS layout), so the relative-gap assertion does not hold. The exemption itself holds: the lobby multiplier in `economy/traffic.rs` applies only to `is_commercial()` kinds. The test asserts the far fast food earns less and reads the exemption from the predicate the income and the card share (`service_diagnostic_facts` lobbyFar: true for the food, absent for the hall).
