# TypeScript engine modules a wasm-only build (VC_ENGINE=wasm) still ships.
#
# scripts/verify-engine-bundle.ts reads every emitted sourcemap after the
# build and fails when the wasm-only bundle carries a src/engine/ module this
# list does not name, or when a listed module no longer ships. The list only
# shrinks: delete a line when its module leaves the bundle, and add one only
# with a reviewed reason the module has to ship.
#
# Why these ship today. The WASM engine alone advances time: the host
# replaces `tick` on every tower it holds, and the TypeScript step loop
# (src/engine/sim/loop.ts) is swapped out of this build. But the app is still
# built around a TypeScript `Simulation` instance:
#   1. It is the read model. The UI, renderer, audio and analytics read
#      `app.sim`, which the host refreshes from the engine's frame view and
#      full save (src/wasmhost/wasmHost.ts, mergeSimulation). Replacing it with
#      an engine-owned snapshot is #868 (cutover AD-4).
#   2. Every player command still runs on the instance first and is relayed
#      to the engine (cutover AD-1, before the 3.0.0 flip).
#   3. Loads and undo restores parse saves with `Simulation.deserialize` and
#      its migrations before the engine boots from them (cutover AD-8).
#   4. A bundler keeps a class's methods whole, so the classes the read model
#      constructs (Crowd, EconomySystem, EventSystem, ElevatorDispatch, Tower)
#      carry their step-time code even though nothing calls it here.
#   5. Reference data and rules the UI reads (catalog, prices, caps) move to
#      the engine's catalog through #921.
#   6. The host-side step driver (fixedStep, timePacing) feeds the engine's
#      tick; it moves into the crate with #867 (cutover AD-2).
# The measured breakdown and the follow-up plan are in
# docs/performance/wasm-only-bundle.md.
