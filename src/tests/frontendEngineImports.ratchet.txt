# The frontend's runtime imports of the TypeScript engine, one line per file:
# the file, then each module under src/engine/ it imports at runtime (its path
# there, without the extension). A "# reason" may follow on the same line.
#
# frontendEngineImports.guard.test.ts scans every non-test file under src/
# except src/engine/, src/tests/ and the host and save code (src/wasmhost/,
# src/dualrun/, src/storage/). It fails when a file imports an engine module
# at runtime that its line does not name, and when a line names a module its
# file no longer imports. Delete a module when its file stops importing it,
# and the line when it names nothing. The list grows only with a reason the
# PR states and a reviewer accepts.
#
# Why it shrinks: the engine is 3.0.0's fallback, and retiring it removes
# src/engine/ (roadmap row 7, "Retiring the TypeScript engine: the inventory"
# in _bmad-output/planning-artifacts/architecture/architecture-engine-rust-port-2026-10-08.md).
# New frontend code reads the catalog, the frame view or an engine query.
#
# The catalog handle (towerCatalog, catalogTypes) is not counted: it is how
# the frontend reads the catalog, and it moves out of src/engine/ before
# retirement.
#
