Expand description

One game of Verticopolis.

Start one with Simulation::new_game, or load one from a save with crate::load::deserialize. Advance it with Simulation::tick and change it only through its commands (build, add_car, adjust_rent and the rest), which apply the rules, charge the money and refuse what a player could not do. The public fields are for reading; writing one skips those rules.

A renderer reads the tower through crate::view or crate::frame, and an analytics or achievements layer drains Simulation::gameplay.

Fields§

§mode: GameMode

The game mode, fixed when the game starts.

§modern_calendar: CalendarKind

The calendar a Modern game runs on. A Classic game always runs the canon calendar.

§auto_bridge: bool

Whether a new floor joins the floor next to it automatically. Only a Modern game can turn this off (Simulation::toggle_auto_bridge).

§founder: bool

Whether the tower was started before saves carried a build stamp. The web game shows these towers a founder badge.

§clock: Clock

The game clock: day, hour, minute, quarter and year.

§crowd: Crowd

The people moving through the tower.

§events: EventSystem

Emergencies, and the choice waiting for the player’s answer.

§tower: Tower

The tower: its floors, rooms and transport. A renderer reads it through crate::view instead of walking it.

§money: f64

The player’s money, in dollars. It can go negative.

§star: i64

The tower’s rating: 1 to 5 stars, and 6 once it is a TOWER.

§milestones: Vec<String>

The milestone ids the tower has reached, in the order it reached them. The ids are stable across versions.

§log: Vec<LogEntry>

The recent messages, oldest first, at most LOG_RING_CAP. crate::frame::log_since returns the ones after a sequence number.

§gameplay: GameplayEvents

The gameplay events since the host last drained them. Call sim.gameplay.drain() after each frame. Never saved.

pub fn with_lobby_height<T>( &mut self, height: i64, run: impl FnOnce(&mut Simulation) -> T, ) -> T

Runs run with height as the height a floor’s first lobby placement asks for (#308), so a lobby built, quoted or brushed inside it on a floor that holds no lobby yet rises that many stories, where the mode lets that floor’s lobby rise. A floor that holds a lobby keeps its height whatever is asked. Outside it, a first lobby is one story. The height is clamped to 1 through MAX_LOBBY_HEIGHT.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
let tiles: Vec<i64> = (100..104).collect();
sim.with_lobby_height(2, |sim| sim.paint_brush(Kind::Lobby, 1, &tiles));
assert_eq!(sim.tower.lobby_height(1), 2);

pub fn paint_brush( &mut self, kind: Kind, floor: i64, tiles: &[i64], ) -> BrushResult

Lays kind (floor or lobby) on each tile column in tiles on floor, charging as that many build calls would, in one command. It skips a tile that already carries kind, and tries a refused tile again once a neighbor it needed is laid, so the order of tiles does not matter.

A lobby brush also turns plain floor into lobby (a sky lobby). Any other kind, or more than BRUSH_TILE_LIMIT tiles, lays nothing and answers INVALID_REQUEST.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
let tiles: Vec<i64> = (100..124).collect();
let laid = sim.paint_brush(Kind::Lobby, 1, &tiles);
assert_eq!(laid.placed, 24);

pub fn build(&mut self, kind: Kind, floor: i64, x: i64) -> BuildResult

Places a floor tile, a lobby tile or a room with its left edge at tile x and its bottom on floor, and charges for it.

A room needs a floor under each of its tiles or bridges the gap when auto_bridge is on, paying for the floor it lays. Floors and lobbies are laid one tile at a time; to lay a run, call paint_brush. A refused build changes nothing. Floor 1 is the ground floor and basements are 0 and below.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
assert!(sim.build(Kind::Lobby, 1, 100).ok);

// Offices open at one star, but not on a bare lot five floors up.
let refused = sim.build(Kind::Office, 5, 300);
assert!(!refused.ok);
println!("{}", refused.reason.unwrap());

pub fn can_build_transport( &self, kind: Kind, x: i64, bottom: i64, top: i64, ) -> CanBuild

The dry run build_transport makes first: whether a shaft of kind at x spanning bottom..=top would be placed, why not, and its full price. Changes nothing.

An elevator costs the catalog cost plus transportFloorCost for each floor past its first; stairs and escalators cost the catalog cost. Refusals come in the build’s order: not unlocked yet, then money, then placement. The price is only a shaft’s price for a transport kind with top above bottom; anything else is refused.

Source

pub fn build_transport( &mut self, kind: Kind, x: i64, bottom: i64, top: i64, ) -> BuildResult

Places an elevator, stairs or an escalator with its left edge at tile x, serving floors bottom to top, and charges for it. A new elevator starts with one car for every six floors it serves, up to its kind’s limit; add_car adds more. Stairs and escalators span exactly two floors.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
for x in 100..124 {
    sim.build(Kind::Lobby, 1, x);
}
for floor in 2..=4 {
    for x in 100..124 {
        sim.build(Kind::Floor, floor, x);
    }
}
let shaft = sim.build_transport(Kind::ElevatorStandard, 110, 1, 4);
assert!(shaft.ok, "{:?}", shaft.reason);

pub fn extend_transport( &mut self, id: i64, end: ExtendEnd, target_floor: i64, ) -> ExtendResult

Moves one end of elevator id toward target_floor, charging TRANSPORT_FLOOR_COST for each new floor. It grows only as far as the money pays for. During a drag, a floor already paid for is not billed again.

use verticopolis_engine::charges::ExtendEnd;
use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
for floor in 1..=6 {
    let kind = if floor == 1 { Kind::Lobby } else { Kind::Floor };
    for x in 100..124 {
        sim.build(kind, floor, x);
    }
}
sim.build_transport(Kind::ElevatorStandard, 110, 1, 3);
let id = sim.tower.transports[0].id;

sim.begin_extend(id);
let grown = sim.extend_transport(id, ExtendEnd::Up, 6);
sim.end_extend();
assert_eq!((grown.bottom, grown.top, grown.added), (1, 6, 3));

pub fn remove_facility( &mut self, id: i64, method: RemovalMethod, ) -> ChargeResult

Removes room or shaft id and refunds half its build price (nothing for a room a fire gutted). method says whether the player sold it or bulldozed it, for the gameplay event. Refused during a bomb search (edit_refusal), for a burning room and for a room the mode keeps for good. Rooms and shafts share one id sequence, so id names exactly one thing.

pub fn rebook_spent_films(&mut self)

Where the mode rebooks spent films (Modern), each screen of an open theater whose film is spent books its policy’s film again, and pays for it. pub fn tick(&mut self, dt_minutes: f64)

Advances the game by dt_minutes game minutes.

Any dt works: the engine splits it into steps of at most 30 minutes that never cross an hour, so hourly rules always run. The same seed, the same commands and the same sequence of dt give the same game. A host that runs on display frames should let FrameStepper choose the dt, so the tower comes out the same at any frame rate.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
let day = sim.clock.day();
sim.tick(24.0 * 60.0);
assert_eq!(sim.clock.day(), day + 1);

pub fn serialize(&self) -> Value

The whole game as save JSON, the object a .vctower file wraps.

A host that edits or inspects the save uses this, then crate::load::stamp_save and crate::load::encode_vctower to write the file. To go straight to the file’s bytes, use crate::load::encode_simulation_vctower.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::sim::{Simulation, PLAIN_SAVE_VERSION};

let sim = Simulation::new_game(3, GameMode::Classic);
let save = sim.serialize();
// A tower with no tall lobby is stamped with the version before them.
assert_eq!(save["version"], PLAIN_SAVE_VERSION);

pub fn tower_signature(&self) -> u64

A fingerprint of the tower, for undo: read it before and after a command, and the command changed the tower exactly when the two differ (barring a 64-bit collision). Money is not part of it; compare that beside it. It walks every room and shaft, so read it once per command; it is too slow to read every frame.

use verticopolis_engine::clock::GameMode;
use verticopolis_engine::facilities::Kind;
use verticopolis_engine::sim::Simulation;

let mut sim = Simulation::new_game(1, GameMode::Classic);
let before = sim.tower_signature();
sim.build(Kind::Lobby, 1, 100);
assert_ne!(sim.tower_signature(), before);
