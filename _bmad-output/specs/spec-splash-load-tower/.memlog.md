- (event) Created from a ratified bmad-party-mode roundtable (2026-07-28) plus the gds-ux run ux-verticopolis-2026-07-28. Rich structured input, so express distill with no elicitation.
- (note) Root problem: appBoot.ts derives hasSave from app.hadReadableSave, which SaveGame.loadResult() reads from the autosave keys only (verticopolis-save, legacy simtower-clone-save). Manual slots 1-3 are never consulted at boot and listSlots() is reachable only from a running game, so the title screen cannot see two thirds of the save system.
- (decision) REJECTED mounting the in-game Saved Towers dialog on the splash: savesTemplate rows carry Save/Delete and the footer carries Export, and on the splash the live sim may be the throwaway boot sim (main.ts: boot.sim ?? Simulation.newGame). saveToSlot would SUCCEED silently (viewState() on a paused-but-alive engine does not throw), writing an empty tower with a real timestamp; Export would emit a .vctower of a tower nobody built.
- (decision) REJECTED routing the action straight to openImport: slot saves live in localStorage where no OS picker can see them, and .vctower is the least reliable surface shipped (openImport carries application/octet-stream in accept precisely because Android greys out unknown extensions).
- (decision) RATIFIED (owner, 2026-07-28): one Load Tower action opens one load-only surface listing device slots (auto + 1-3) WITH 'Load from a file...' as a row in that same list. The player picks a tower, never a storage mechanism.
- (capability) CAP-1 splash action stack: Load Tower always rendered, order Continue / Load Tower / New Tower, never primary in any state.
- (capability) CAP-2 load-only tower picker: one row per device slot by RAW presence, load action on parseable rows only.
- (capability) CAP-3 file row in the same list, routed to the existing .vctower/.TDT importer.
- (capability) CAP-4 empty and all-unreadable states: one honest line plus the file row, never four rows reading 'empty'.
- (capability) CAP-5 dismissal invariant: the title screen is dismissed by a tower ARRIVING, never by a dialog opening.
- (capability) CAP-6 a load from the splash lands paused at speed 0 under the same contract onContinue already honors.
- (decision) Order is Continue / Load Tower / New Tower: New Tower is the only action that can cost the player something, so it sits furthest from the default focus and from the Esc/backdrop safe dismiss. Primary styling unchanged (Continue amber, or New Tower amber when no save exists); Load Tower is never amber, so exactly one amber plate is on screen at a time.
- (decision) Label says Tower not Save: the product says tower everywhere (Saved Towers, Tower loaded, New Tower) and a save is a file format.
- (constraint) Presence is the raw hasSlot check (getItem !== null), never the parse-based listSlots().exists, so a corrupt-but-present slot is SHOWN and labeled 'Couldn't be read by this version.' rather than hidden. Hiding it would claim the tower is gone when preserveUnreadable exists precisely because a newer-build save may be recoverable later. An unreadable row carries NO control, not a disabled one.
- (constraint) No Save, Delete, or Export on any surface reachable from the title screen. This is correctness, not taste: the standing invariant (saveLoad.ts saveBeforeUpdate comment, enforced by the 30s autosave timer's #splash check) is that nothing mutates the sim while the splash is up.
- (constraint) The picker uses the shared retro <dialog id=modal> shell, as How to Play and the New Tower picker already do over this same screen; it inherits the safeDismiss guard that stops the splash's own Esc firing underneath an open modal. The splash itself stays un-unified box art.
- (constraint) Focus: the new plate joins the splash focus trap in DOM order but must NOT become the fallback focus target (Onboarding.ts:240 focuses [data-splash=continue] ?? [data-splash=new]); the existing assertion that mute and install are the last two in tab order must still hold; scripts/screenshot-page-ops.ts:232 selects the same continue/new pair and must keep working.
- (constraint) Reuse the existing seams: SaveGame.listSlots/hasSlot/loadSlot, loadFromSlot's adoptSim path, and openImport. No new persistence format, no new storage key.
- (assumption) The picker reuses .slot row styling; verify at implementation that a row with no action buttons still reads as a row rather than a heading.
- (assumption) Three plates plus the ghost link fit one desktop row at current sizes (.splash-actions already wraps). The mobile stack gains a fourth full-width 48px control; verify at 360x640 that it clears .splash-attrib and does not push the wordmark off screen.

- (question) OPEN: does a splash load flush the outgoing tower first? importLegacy's onOpen calls saveBeforeUpdate() before adopting, but on the splash the outgoing sim is usually the throwaway boot sim and the #splash guard makes the flush a no-op anyway. Decide deliberately rather than inheriting the import path's flush by accident.
- (event) Spec finalized 2026-07-28. Implementation not started; no source files touched.
- (decision) RESOLVED the open question (does a splash load flush the outgoing tower first?): NO explicit flush, and no code change needed. The .TDT path's saveBeforeUpdate() already no-ops behind the #splash guard, and on the title screen the outgoing sim is either the throwaway boot sim (nothing to preserve) or the player's autosave, which the splash's own freeze keeps byte-identical to storage. Adding a flush would only risk writing the throwaway sim. Left the existing import call sites untouched.
- (decision) CORRECTION to CAP-2/CAP-5 as originally written: a failed slot load must NOT toast. Implementation found the title screen paints over the toast rail (#toast-wrap sits inside #stage with no z-index; #splash is fixed at z-index 40), so a toast raised from the picker is feedback the player never sees. The picker re-renders with the reason inline instead (role=alert), and loadFromSplash returns a boolean rather than toasting. Its counterpart loadFromSlot, which runs mid-game where the rail IS visible, keeps toasting.
- (decision) Separately raised #toast-wrap to z-index 45 (above #splash at 40, below #boot-cover at 50, which is gone before any toast can fire). Needed for CAP-3: a rejected .vctower or .TDT reports through importGame/importLegacy's existing toasts, and those were invisible behind the title screen. Also fixes the pre-existing case of install-path toasts raised while the splash is up.
- (decision) The CAP-5 dismissal junction is OnboardingController.adoptSim, not GameApp.adoptSim as first drafted. GameApp.adoptSim already calls it, so the behavior is identical, and the controller is the module that OWNS the splash. Practical driver: the file-size guard (500 lines, ratchet-only-shrinks) put main.ts at exactly the ceiling, so the hook had to live where there was room. The re-pause and greeting come back to the host through a new optional OnboardingOpts.onEnterTower, wired in appBoot.
- (constraint) The 500-line file-size guard forced two splits this change had to carry: the picker controller lives in its own src/ui/uiTowerPicker.ts (re-exported from uiDialogs, exactly like uiBatchPricing and uiElevatorSchedule), and uiBatchPricing's dialog ctx/cb shapes became named exported interfaces (BatchPricingDialogCtx/Cb) so UI.ts's delegation references them by name instead of restating them. Adding paths to fileSize.ratchet.txt was not an option: it only ever shrinks.
