- (event) D-1 ruling context: the full-repository-audit (2026-07-21) opened D-1 (issue #542), Vercel Web Analytics vs cookieless PostHog, auditor recommending migrate. A first party on stale data said cut; a reanalysis said Vercel-now-PostHog-on-trigger; then a fresh 2-day analytics-report run, validated live (prod serves the insights and speed-insights scripts HTTP 200, the event endpoint 400-validates, and every custom event is wired to a real game action), returned 329 sessions / 197 boots / ~113+ unique visitors in TWO days, not the audit 12-per-30-days. The trigger fired. Owner RULED: migrate.
- (decision) Ruling: migrate to cookieless PostHog, seam-first, behind a keyless same-origin reverse proxy, with a measured mobile bundle budget as a hard gate and a dual-write validation window before Vercel is retired. The transport-agnostic event enrichment ships in parallel. Retention stays out of scope because cookieless PostHog has no cross-session identity either.
- (capability) CAP-1 one-file analytics adapter seam. intent: the vendor and transport live in exactly one adapter module; the typed note-vocabulary and every call site (game_started, first_build, tool_used, star_reached, boot, crash, update, plus the session-depth events) are unchanged; a provider swap is a one-file diff. success: no vercel-analytics or posthog import exists outside the adapter; a stub adapter drives the whole vocabulary in tests; switching transports touches exactly one file.
- (capability) CAP-2 cookieless PostHog transport via a same-origin serverless relay (no posthog-js SDK). intent: the CAP-1 adapter POSTs typed events (event name plus props, no key, no cookie) to a same-origin ingest path served by a Vercel edge/serverless function that forwards to the PostHog capture API with the project key read server-side from the environment; posthog-js is NOT shipped, so there is no SDK bundle weight and no key in the client. Within-session correlation comes from a per-session distinct_id generated in memory at boot and never persisted, so cross-session identity is deliberately absent. The mechanism is documented in the reverse-proxy.md companion. success: the shipped bundle contains no PostHog SDK and no project key; a network trace shows events posting to the same origin, never a PostHog domain; no cookie or persisted id is set; events in one play session share an in-memory id while a new tab starts fresh; disabling the transport degrades to best-effort no-throw.
- (capability) CAP-3 event enrichment that pays off with per-session correlation. intent: add the platform dimension web/twa/ios as an event prop (resolving AUD-036), model the first-tower funnel game_started then first_build then star_reached(2) as a real funnel, keep the on-device returning signal (cookieless has no cross-session id, so returning stays derived on-device off the onboarding-seen flag), and unlock the per-tool and per-session splits the Vercel report could not compute. success: PostHog shows a platform breakdown, the three-step funnel with real drop rates, returning-vs-new by depth, and per-tool per-session distributions.
- (capability) CAP-4 report re-target and tooling retirement. intent: retarget the analytics report to PostHog queries and retire the percentile-reconstruction machinery in analytics-report.mjs once cutover is confirmed; session_fps (issue #538) emits raw values into the surviving stack. success: exact percentiles and per-session correlation come from PostHog queries, not histogram reconstruction; the analytics-report.mjs percentile code is deleted on cutover; the AUD-034 truncation caveat is gone.
- (constraint) Cookieless and consent-free by construction: PostHog in memory-persistence mode, no cookie, no localStorage identifier, no cross-session or cross-device identity, and no consent banner as the price of pressing Play. The privacy posture is unchanged from the Vercel baseline; this is the load-bearing invariant.
- (constraint) No project key in the public bundle: a same-origin reverse proxy forwards events to PostHog server-side; the write key lives in the deployment environment, never in the shipped bundle; the proxy is rate-limited against abuse.
- (constraint) Near-zero mobile bundle, verified: because posthog-js is NOT shipped (events flow through the thin same-origin relay), the client delta is a small fetch or sendBeacon adapter, not a ~50KB SDK. The gzipped delta and any cold-start cost are still MEASURED on a mid-tier phone against the render-perf error budget and must stay under a concrete ceiling (a net delta of at most 5 KB gzipped with no measurable cold-start regression; the implementation PR records the number); render performance is the audit number-one risk, so this is a hard gate, not advisory.
- (constraint) One gate for every surface: telemetryHostAllowed stays the single predicate every telemetry call obeys; the native Capacitor shell, localhost, and the e2e vite preview server stay dark by it (Vercel preview deployments on *.vercel.app do emit, tagged environment=preview, for pipeline validation); no second divergent gate. The typed vocabulary and the never-throw best-effort guarantee are preserved across the swap.
- (constraint) Dual-write validation window: for a short window both Vercel and PostHog receive events in parallel; Vercel is retired only after the two agree on the headline counts. Speed Insights (Core Web Vitals) is a separate keep-or-drop decision recorded at swap time.
- (constraint) Process: spec-first; the decision is ruled, then the work sequences as seam, reverse proxy, cookieless transport swap, event enrichment, report re-target, dual-write, retire. Each PR passes four quality gates and gds-code-review in-session (analytics correctness is gameplay-progression semantics, per the TDT-is-storage-but-gds-reviewed precedent); the player-facing what-we-measure note is updated; a version bump applies only where a player-facing surface changes.
- (decision) Non-goal, parked and named: the true cross-session cohort retention curve (day-7 and day-30 unique-return rate), churn, and per-cohort funnels. Cookieless PostHog has no cross-session identity, so this migration does NOT unlock retention; it remains gated on a future funded identity decision (the E4 monetization gate).
- (constraint) Non-goal, out: cookies, any cross-session or cross-device identifier, a consent banner, session replay, autocapture, DOM or pointer or keystroke capture, PII, raw IP, and any PostHog project key in the shipped bundle. Native-shell (iOS) telemetry stays a separate decision; this spec does not turn it on.
- (direction) The reverse-proxy mechanism is documented in a spec-authored companion, reverse-proxy.md: the same-origin /ingest edge function, the server-side key, the cookieless in-memory per-session distinct_id, rate-limiting, the region host, the dual-write path, and a flow diagram. Cited from CAP-2 and the no-key-in-bundle constraint.
- (note) Success signal: after cutover, PostHog answers what Vercel only approximated (exact percentiles, per-tool and per-session splits, a real first-tower funnel, and a platform breakdown), at a measured mobile bundle cost under the stated budget, cookieless and banner-free, with dual-write parity confirmed before Vercel is retired and the analytics-report.mjs percentile machinery deleted.
