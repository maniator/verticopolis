- (direction) Owner asked (2026-07-22) whether to nudge non-installed users to install; routed to game+design party, then bmad-spec; platform/UI plumbing not a game mechanic, so /bmad-code-review track
- (decision) Party ruling round 1: NOT a toast (repeats the interruption pattern being stamped out); an ambient/pull affordance, outcomes-not-tech copy, measure silently; iOS has no programmatic install so never fake one-tap there
- (decision) Party ruling round 2 (the 'not on splash' refinement): install is an IN-GAME affordance, not a splash one; splash mute stays splash-only, install stays in-game, zero overlap
- (capability) CAP-1 conditional in-game install chip in the topbar appear/disappear zone (update-chip neighbor), live condition in-game AND installable AND not-standalone; first appearance gated on real play (splash dismissed into a tower / first placement), shown once quietly, then retreats to a permanent-but-passive Game-panel entry (beside Saves/Settings). No re-nagging.
- (capability) CAP-2 Android/desktop Chrome-Edge one-tap install: capture beforeinstallprompt, preventDefault + stash the deferred event, chip/menu calls prompt(); the event is only ever consumed through deliberate UI so a stray dismissal cannot burn it
- (capability) CAP-3 iOS Safari opt-in Add-to-Home-Screen how-to: same affordance present, opens an honest short how-to ON TAP only, never auto-shown, never disguised as one-tap (iOS fires no beforeinstallprompt and has no programmatic install)
- (capability) CAP-4 silent adoption measurement: appinstalled event + a boot display-mode bucket (standalone vs browser) into the EXISTING cookieless analytics (analyticsEnrichment.ts); no player-facing telemetry nag
- (constraint) No player-facing 'PWA' / 'install our app' wording anywhere; copy is outcomes: play offline, fullscreen, from your home screen
- (constraint) Already-installed (display-mode standalone / navigator.standalone) and Android TWA sessions must see the affordance NOWHERE
- (constraint) beforeinstallprompt is consumed only through deliberate UI (guard the one-shot); the how-to on iOS is never auto-shown
- (constraint) Reuse the update-chip (#btn-update) appear/disappear plumbing; introduce no new timed pop-up/toast region
- (constraint) No dark patterns, no re-nagging: shows once then goes passive; respects the player
- (decision) Non-goals: any splash install offer; timed/auto pop-ups or toasts; win-moment/star-gated triggering (explicit PHASE-2 only if the plain chip underperforms); the word PWA in UI; any change to first-visitor autoplay or the update flow
- (assumption) 'Installable' == the beforeinstallprompt event has been captured this session; if a browser never fires it (criteria unmet) the chip simply stays hidden there, which is acceptable
- (assumption) matchMedia('(display-mode: standalone)') plus navigator.standalone (iOS) reliably identify an already-installed session for the not-standalone gate
- (event) Self-validate pass 1 (coherence): 4 capabilities each intent+success; 6 constraints all design-bending; 5 non-goals; concrete multi-platform success signal; 2 assumptions (installable=event-captured, standalone detection), 0 open questions. Spec Law 1-6,8 satisfied.
- (event) Self-validate pass 2 (preservation): every party claim landed (in-game-not-splash, chip+passive-menu, one-tap Android/desktop, iOS opt-in how-to, silent analytics, outcomes-copy, TWA/standalone invisible, one-shot guard, phase-2 win-gate deferred). No companion needed (no catalogs/diagrams). Routing framing dropped as ceremony.
- (direction) Owner override (2026-07-23): observed on the live mobile splash that there is no install option and wants one there too; a mobile splash view is a prime install moment. The former non-goal 'any splash install offer' is promoted to a capability.
- (capability) CAP-5 splash install control: a quiet install button on the splash (near the mute, un-unified box-art styling), shown ONLY when installable (installAvailability !== none), revealed live if beforeinstallprompt arrives while the splash is up; tapping it drives the same offer as the in-game affordance (native prompt on Chrome/Edge, iOS how-to on iOS); hidden for standalone/TWA and for a browser that never becomes installable.
- (constraint) One offer, three surfaces (splash button + topbar chip + Game-panel entry) all drive the same activate path and the same installAvailability; no second capture, no duplicate prompt event.
- (note) Chrome gates beforeinstallprompt behind an engagement heuristic, so the splash button is often hidden on a brand-new first paint and reveals on a returning/engaged visit; documented, not a defect.
- (event) Re-derived after owner override: added CAP-5 (splash install), promoted the splash non-goal to a capability, added the one-offer-three-surfaces constraint. 5 capabilities, still preservation-clean.
- (direction) Owner + party (2026-07-23): splash install is a PERSISTENT front door, shown for any not-standalone session (not gated on beforeinstallprompt). Tap degrades gracefully: native prompt if event captured, else an honest how-to. Requires a Chrome/Edge browser-menu how-to variant alongside the iOS one. In-game chip keeps its stricter capture-gated, show-once rule. Simpler than the reveal-race design (no live event watch for splash visibility).
