- (constraint) The file is pre-sanctioned, not a new decision: PRD F5 names it as the verification file the public repo serves, PRD N2 lists it and the Android application ID as protocol-public exceptions, arch line 71 fixes the path, epics line 69 defines story E2b as version:none infra work.
- (note) Live URL returns 404 today, recorded independently by curl and by the repo's own production-validation baseline (scripts/s1-baseline.mjs). The full-repository audit already classifies this as the known Android blocker, not a defect.
- (decision) Delivery needs NO build, hosting or script change. Vite root is src and publicDir defaults to src/public, and Vite 7.3.6's copyDir is a bare readdirSync recursion with no dotfile filter, so .well-known survives the copy verbatim; vercel.json has framework:null, outputDirectory:dist and no SPA catch-all, so the path is served as a static 200 with application/json inferred.
- (decision) sha256_cert_fingerprints is an ARRAY carrying one fingerprint today, from a sideload key held only on the owner machine and never committed to either repo. This unblocks sideloading a verified test APK now, and the array is the seam the Play App Signing fingerprint joins later.
- (constraint) The Play App Signing fingerprint CANNOT be included yet: arch line 72 records that it only exists after the Play Console app record and enrollment, which is why the original E2b was sequenced after that checkpoint. Shipping the array early is what decouples the two.
- (decision) OWNER DECISION, reversible: listing a locally-held key means any app signed with it is trusted to act as a verified TWA for verticopolis.com. Accepted because the key never leaves the owner's machine and the entry is one line to remove; it must be removed at store launch once the Play fingerprint lands.
- (capability) CAP-1 Digital Asset Links verification: the file is live and correct, so Android accepts the app as owning the domain. Success: 200 with application/json at the exact URL, Google's asset-links tester passes for io.github.maniator.verticopolis, sideloaded APK shows no Custom Tab chrome.
- (capability) CAP-2 honest manual verification: a tester opening the URL in a browser tab sees the JSON, not the game shell. Success: /.well-known/ is on navigateFallbackDenylist beside version.json, robots.txt and sitemap.xml, so the service worker stops answering that navigation with index.html.
- (capability) CAP-3 the file cannot silently vanish: a build-time guard fails the build if it is missing or malformed. Success: a verify script in the verify:dist chain asserts dist/.well-known/assetlinks.json exists, parses, and carries the package name plus at least one 64-hex-pair fingerprint; setting copyPublicDir:false or moving root turns the build red.
- (constraint) No version bump and no CHANGELOG player note: nothing a web player observes (CONTRIBUTING line 298, epics line 69 'version: none (infra)').
- (note) Workbox globPatterns exclude json, so the file is never precached, which is what we want: verification must read the live file, not a cached one. No exclusion entry needed.

- (constraint) OPERATIONAL HAZARD found while verifying: Vercel Deployment Protection answers EVERY path with a 302 to vercel.com/sso-api, including /robots.txt and /version.json. Google's Digital Asset Links verifier fetches anonymously, so enabling protection on the production domain would silently break Android verification and the app would degrade to a browser bar with nothing in this repo changing. Production is unprotected today (verified). Anyone turning protection on must exempt /.well-known/.
