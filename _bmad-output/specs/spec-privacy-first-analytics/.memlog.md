topic: Privacy-first player-depth analytics: execute E1e by extracting a one-file analytics seam and closing the first-tower funnel plus returning-player depth on the existing cookieless Vercel feed, without migrating to a second platform
updated: 2026-07-21T21:50
---

- (event) Upstream: installed-room analytics party (session mode, 2026-07-21; party memlog 144-148) ruled 5-1 against migrating to PostHog. The only unique buy of a second platform is a cross-session retention curve, which needs a persistent identifier, which re-arms a consent banner the project will not ship, and which cookieless PostHog cannot deliver anyway. This spec executes the party answer: join identity on the device, emit anonymous aggregates, close the gap on the feed already owned.
- (direction) Owner ruled scope: both tiers in. A-free is a returning boolean read off the existing onboarding-seen flag (zero new state). A-rich is coarse tenure and sessions buckets from one purely-local, never-transmitted first-seen-plus-boot counter.
- (note) Current state: the Vercel Web Analytics custom-event feed (src/analytics.ts) is cookieless, gate-parity-clean, consent-free, and already answers tool mix, crash reliability, and update adoption; it does not answer where the first-tower funnel leaks or whether returning players climb higher. Refines mobile-PRD decision-log entry 13 (F8/E1e), which picked a privacy-first cookieless class for E4 monetization data; the shipped tool is Vercel, also cookieless, so no Plausible or Umami swap is needed.
- (capability) CAP-1 one-file analytics seam. intent: the vendor and transport call lives in exactly one adapter module; bootstrap, gallery, helpPage, and the game loop keep calling the typed gameplay vocabulary, so a provider swap is a one-file diff. success: no vercel-analytics import outside the adapter; the Vercel channel behaves byte-identical behind the existing telemetryHostAllowed gate; a stub adapter drives the whole vocabulary in tests without a vendor SDK.
- (capability) CAP-2 first-tower funnel as ordered steps. intent: game_started then first_build then star_reached(2) reads as a three-step funnel with fresh foundings as the denominator, exposing the two drop points (founded but never built; built but never rated). success: the events already fire in this order for a founded tower so no new event type is needed; the funnel, denominator, and drops are documented and shown; a test pins that a fresh founding emits game_started before its first_build.
- (capability) CAP-3 returning-player depth via on-device join and anonymous buckets. intent: answer do returning players climb higher as a cross-tab of return status against progression, with no identifier leaving the device. success: the boot event carries a returning boolean off the persisted onboarding flag plus coarse tenure and sessions buckets from a purely-local counter; the dashboard cross-tabs them against star_reached; no cookie, banner, or raw value is transmitted.
- (constraint) Cookieless by construction: no cookie, no localStorage identifier transmitted, no cross-session or cross-device identity built, and no consent banner as the price of pressing Play. This is the load-bearing invariant the spec exists to honor.
- (constraint) The local counter never leaves the device raw: the first-seen timestamp and boot tally are read only to derive a coarse bucket; the raw values are never sent. A precise first-seen millisecond is quasi-identifying; a coarse month1-plus bracket is not.
- (constraint) Coarse buckets only, for k-anonymity: at most four brackets each (tenure in new, day1, week1, month1-plus; sessions in 1, 2-5, 6-20, 20-plus), chosen so no single cross-tab cell narrows to one player on the current population; boundaries revisited if a cell nears uniqueness.
- (constraint) One gate for every surface: telemetryHostAllowed stays the single predicate every telemetry call obeys; the native Capacitor shell, localhost, and the e2e preview stay dark by it; no second divergent gate.
- (constraint) Rides the existing boot event, no new event type: returning, tenure, and sessions are added props on the boot snapshot, preserving the low-volume vocabulary that fits the Vercel event budget.
- (constraint) Best-effort and never-throw preserved: a missing or corrupt counter degrades to omitting the field rather than throwing into boot or the game loop.
- (constraint) Near-zero bundle: the spec stays on the Vercel channel and adds no SDK; any future SDK would be lazy-loaded off the boot path with a measured mobile delta, out of scope here.
- (constraint) Decision per metric: every field names the decision it would drive and the threshold that flips it; a field that names no decision does not ship.
- (constraint) A player-facing transparency note ships with the change (companion transparency-note.md), stating the game counts how far returning players get and never who they are; that copy is player-facing, so the PR takes a patch version bump though the telemetry is internal.
- (constraint) Process: one PR carries the seam, the CAP-3 fields, the funnel documentation, the transparency note, and tests; four quality gates green and gds-code-review in-session, because the correctness at stake is gameplay-progression semantics, per the TDT-is-storage-but-gds-reviewed precedent. Implementation is a separate PR after this spec.
- (decision) Non-goal, cut: migrating to PostHog or any second analytics platform. It re-pipes three answers already owned, adds a vendor, a CSP surface, and a public write key in a public repo, and cannot answer retention cookielessly.
- (decision) Non-goal, parked: self-hosting an analytics backend, the only road that can ever answer a true cohort retention curve, unlocked only if the owner funds identity plus operations against a named decision; the E4 monetization gate of mobile-PRD entry 13 is the likely trigger.
- (decision) Non-goal, parked and named: the true cohort retention curve (day-7 and day-30 unique-return rate), churn, and per-cohort funnels; they require cross-session identity the project is choosing not to build, and are never faked with a cookieless proxy.
- (constraint) Non-goal, out: any cross-session or cross-device identifier, cookie, or consent banner; native-shell telemetry (the iOS Capacitor shell stays dark, no App Store data-disclosure change); session replay, autocapture, DOM or pointer or keystroke capture, PII, and raw IP.
- (note) Success signal: within one sprint of shipping, the Vercel dashboard answers both open questions (the first-tower funnel drop percentages at each step, and a returning-by-depth cross-tab of returning and the tenure and sessions buckets against star_reached), with no consent banner, a near-zero bundle delta, and the transparency note live. If the funnel and cross-tab are not live and answering within a sprint, E1e is not shipped and its backlog row stays open.
- (assumption) The onboarding-seen flag is a fair proxy for a returning browser: it is per-browser and clears on cache-clear or private browsing, so the signal is browser-return rather than person-return; that ceiling is accepted, since the alternative is the persistent identifier this spec refuses.
- (assumption) Vercel Web Analytics accepts a boolean and two coarse bucket props on the existing boot event within the event budget; these are low-cardinality dimensions, not a per-user identifier.
- (assumption) The seam extraction is behavior-identical for the Vercel channel; the existing analytics and telemetry tests plus a stub-adapter test pin that the vocabulary and the host gate are unchanged.
- (event) Self-validate pass 1 (coherence, Spec Law 1-6 and 8): PASS. Three capabilities each carry intent and success; intents state WHAT not HOW; every constraint bends a design decision; five explicit non-goals; the success signal is demonstrable (a live dashboard funnel and cross-tab within one sprint); CAP ids stable and unique; prose is lean.
- (event) Self-validate pass 2 (preservation): PASS. Every load-bearing claim from the party decision and the owner scope ruling lands in SPEC.md or the transparency-note companion; wrapper ceremony dropped. SPEC derived from the memlog; spec finalized.
