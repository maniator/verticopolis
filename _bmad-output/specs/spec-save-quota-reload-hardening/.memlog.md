topic: Harden SaveLoad.recoverFromContextLoss so a localStorage failure during the pre-reload flush can't abort WebGL context-loss recovery
updated: 2026-07-06T20:38

- (direction) Backlog P2 (pr-110-compress-saves), bmad/persistence lane; already implemented on branch claude/copilot-code-review-bmad-afbj08 (PR #136). Spec is the canonical contract for the bmad-code-review Acceptance Auditor.
- (decision) Guard the context-loss pre-reload flush in try/catch: a localStorage quota/private-mode/SecurityError throw was escaping onContextLost and aborting location.reload(), stranding the player on a dead GPU canvas with no message.
- (capability) CAP-1: on a context loss whose pre-reload save throws, show the boot card (with a Reload button) instead of aborting recovery. success: a failing flush yields exactly one boot card (withReload=true) and location.reload() is NOT called.
- (capability) CAP-2: tailor the card copy to reality — promise the prior tower is safe only when SaveGame.hasSave() confirms one exists. success: prior-save present -> copy contains 'last saved tower is safe'; absent -> it does not.
- (constraint) The in-catch hasSave() read must be guarded in its own try/catch: getItem also throws when storage is DISABLED (SecurityError), and an unguarded read would re-throw before the card shows, re-aborting the reload.
- (constraint) A failed setItem is atomic (never clobbers), so the prior autosave survives — no write-to-temp-then-swap needed.
- (constraint) saveTo must keep throwing: the update path (saveBeforeUpdate in main.ts) relies on the throw to pause the update rather than reload.
- (constraint) Card copy must be accurate for BOTH failure classes: 'storage is full or blocked … free up space or allow site storage' (Copilot review: 'free up space' alone is wrong for the storage-disabled case).
- (note) Non-goal: do not change the already-guarded update path or PR #110's compression/quota-headroom mechanics; do not add cross-reload post-recovery toast signaling (the card is the notification).
- (event) Self-validate pass 1 (coherence): PASS — CAP-1/CAP-2 each carry intent+success; constraints all bend design; 1 non-goal minimum met (3); success signal is demonstrable.
- (event) Self-validate pass 2 (preservation): PASS — every load-bearing claim (guard, atomic-setItem, hasSave guard, saveTo-still-throws, dual-cause copy, non-goals) landed in SPEC.md. No wrapper-only drops.
- (event) Spec finalized; implemented + reviewed on PR #136 (bmad-code-review Acceptance Auditor audited against these 2 capabilities).
