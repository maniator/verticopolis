- (note) Follow-up to the merged cookieless error tracking (analyticsErrors.ts, $exception via same-origin relay); part of the analytics-posthog-migration epic; base already ships uncaught-error + unhandledrejection capture.
- (decision) Why: the shipped tracker only sees GENUINELY uncaught errors, but the #1 real crash (WebGL context loss / #538) is handled (fires the typed crash event) and never becomes uncaught, so PostHog Error Tracking is empty of the crash that matters; and there are no error dashboard tiles.
- (capability) CAP-1: WebGL context-loss crashes surface in PostHog Error Tracking as a synthetic $exception IN ADDITION to the existing typed crash analytics event (keep both; two lenses on one incident). intent: a WebGL crash appears as a grouped Error Tracking issue. success: a webgl-context-lost crash on an allowed host produces one $exception (type WebGLContextLost, mechanism handled:true synthetic:true, stable fingerprint) AND the crash event still fires; neither is suppressed.
- (capability) CAP-2: reported exceptions carry a top-level $exception_type so a dashboard trend can break errors down by type. intent: analysts break errors down by type without reaching into the nested $exception_list. success: every emitted $exception has a top-level $exception_type equal to the exception type; a PostHog trends breakdown by it separates error kinds.
- (capability) CAP-3: an error-tracking section is provisioned into the dashboard as code (scripts/posthog-dashboard.mjs): errors over time, top issues by $exception_fingerprint, by platform, by build version, by type. intent: at-a-glance error volume/trends live on the committed, reproducible dashboard. success: running the provisioning script creates/updates those tiles idempotently; the committed script is the source of truth.
- (constraint) Cookieless/consent-free: no cookie, no localStorage id, no cross-session/cross-device identity, no consent banner. The synthetic crash $exception carries only the per-tab session id and common props, never an identifier.
- (constraint) No posthog-js shipped; the synthetic $exception flows through the same relay-only sendException; single telemetryHostAllowed gate re-checked per report; best-effort never-throw on the crash path (a reporting failure must never break crash recovery); relay forwards no IP (GeoIP disabled).
- (constraint) crash and $exception must not mislead as a double-count: they are two lenses on one incident (crash = structured analytics fields repeat/recoveryFailed/saveFlushed/behindSplash; $exception = Error Tracking issue). Documented so nobody sums them as total errors.
- (constraint) Bundle delta stays under the 5 KB gzipped ceiling with the measured number recorded in the PR; version bump only where a player-facing surface changes (a new client-emitted event category is player-observable like session_fps/S5b, so a minor bump if the synthetic emission is new client behavior).
- (non-goal) Structured stack-frame parsing + source-map upload (so PostHog resolves frames instead of the raw string) is out of scope, tracked separately.
- (non-goal) Tower-name / player-authored free-text scrubbing from exception messages is out of scope (tracked as #607).
- (non-goal) Replacing the typed crash event with $exception is a non-goal: the crash event's structured fields are kept for analytics; $exception is additive.
- (event) Self-validate pass 1 (coherence): PASS. CAP-1/2/3 each have intent+success; intents are WHAT; constraints bend design; 3 non-goals; success signal concrete/testable; CAP IDs unique.
- (event) Self-validate pass 2 (preservation): PASS. All load-bearing input claims landed (WebGL synthetic $exception, top-level $exception_type, dashboard tiles, cookieless/no-posthog-js/one-gate/never-throw/no-IP, bundle+version, three non-goals). No load-bearing drops.

Rationale (Mary): breaks down by action in one insight; these actions carry near-zero props; promote to a typed event later only if one needs a rich shape. Keep the union closed for discoverability.

- (decision) PARTY: speed = KEEP but COARSE. Fire app_action('speed') ONCE per session, session-latched, on the first non-pause speed change ('did this session ever run the sim'). Not per-click. One bit.
