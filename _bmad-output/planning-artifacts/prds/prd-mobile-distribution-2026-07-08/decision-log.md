# Decision Log: prd-mobile-distribution-2026-07-08

All entries 2026-07-08, headless create run. Decisions were fixed in a user-approved plan before this PRD was drafted; this log records them and the drafting choices made here.

1. **TWA first for Android; Capacitor Android deferred.** User decision. Rationale: the PWA is production-grade and live on a custom domain, so TWA is the shortest path to the Play Store; Capacitor effort concentrates on iOS, which has no TWA equivalent.
2. **iOS via Capacitor with bundled web assets, CI-only builds.** User decision (no local Mac). Bundling chosen over remote loading to reduce Apple 4.2 risk and give offline play.
3. **Two-repo split.** User decision: public MIT repo stays free of store identity and monetization; private `verticopolis-mobile` repo holds wrappers, store config, CI, monetization. Exception recorded: `assetlinks.json` is served from the public repo because verticopolis.com is this repo's deploy and the file is public by protocol.
4. **assetlinks served from this repo rather than a user-site repo.** Drafting-time correction: the game runs at the custom domain https://verticopolis.com (not a github.io subpath), so `src/public/.well-known/assetlinks.json` in the public repo reaches the origin root (Vite's `root` is `src`, making `src/public/` the effective publicDir). Removes a cross-repo dependency an earlier draft assumed.
5. **PRD instead of GDD.** There is no game design content in this effort; a GDD would be padding. The arch and epics docs pair with this PRD; the deviation is noted in their front matter.
6. **Version mapping rule** (`versionCode = major*10000 + minor*100 + patch` + CI offset + private ledger). Chosen for determinism; the offset input covers same-version re-releases, which the formula alone cannot. **Superseded by entry 11:** adversarial review showed this formula collides at two-digit patch numbers and the offset consumes future versions' codes. The adopted scheme is `major*1000000 + minor*10000 + patch*100 + seq` with a ledger monotonicity check, as stated in PRD F7 and arch §6.
7. **Done-gates stop at Play internal track and TestFlight.** Production rollout is a human decision after real-device validation and (for Play) the closed-testing requirement.
8. **Monetization excluded entirely** from this PRD beyond policy constraints that shape later choices (Play Billing in TWA). Strategy phase runs later, in the private repo, behind a user sign-off gate.
9. **E1 story version tags corrected from the plan's `patch` to `none`.** The approved plan tagged E1a-E1d `version: patch`, but their own acceptance criteria require identical browser behavior, and CONTRIBUTING reserves bumps for player-facing changes. Repo rules win over the plan detail.
10. **E1b-E1d reviews routed to `/bmad-code-review`** (storage/build tooling per CLAUDE.md routing) instead of the plan's blanket `gds-code-review` for E1; E1a and E3b keep `gds-code-review` as game-facing. Every E2/E3 story now names a review skill.
11. **Adversarial review triage (2026-07-08, three-layer bmad-code-review of this planning set).** Fixed in place: the versionCode scheme widened to `major*1000000 + minor*10000 + patch*100 + seq` with a ledger monotonicity check (the old formula collided at two-digit patches and the offset input consumed future codes); iOS CFBundleVersion uses the same code only (a run-number alternative would violate App Store Connect's increasing-build rule); F1/F2 now state that the Android TWA runs the plain web build with the full PWA update flow (the native flag and SW gating apply to the bundled iOS wrapper); the iOS shell-injection mechanism is specified (CI patches the copied index.html to load native-shell.js first); Play App Signing is mandated with offline keystore escrow; a `.vctower` UTI declaration was added to E3a; E2 was resequenced so assetlinks (E2b) follows the app-record/enrollment checkpoint that produces the Play signing fingerprint; E1d now owns creating the repo's first release tag (none exist today) and no longer claims an empty `.well-known/` directory as a deliverable; E1c's file:// smoke check was replaced with a local-server check (module scripts are CORS-blocked from file://). One finding was refuted by the code: vite.config.ts:62 sets `injectRegister: false`, so gating src/pwa.ts is sufficient (now cited in arch §3). No findings deferred.
12. **Private-repo topology ratified by party roundtable (2026-07-08): consumer repo + tracked `PUBLIC_REF` file.** The owner asked whether the private repo should be a full-history mirror kept in sync or a submodule shell. Room (Cloud, Winston, Link, John, plus review-crew walk-on) converged on keeping the consumer shape and adding a one-line `PUBLIC_REF` file so the iOS build pin is declarative and reviewable, which was the submodule's only real advantage. A mirror carries permanent sync toil plus a two-remote leak hazard, and can be created in minutes later if the E4 monetization gate decides on private game-code changes. Key reframe: Android is always in sync by construction (TWA renders the live site) and iOS is pinned on purpose (reproducible store snapshots), so continuous repo sync serves no job.
