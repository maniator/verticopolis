# Decision log — Verticopolis tablet breakpoint

Scope: a responsive **tablet** layout tier for the browser client. Not a full-game
UX pass — the spines here cover only the responsive/layout concern.

## Evidence (real app, captured via `scripts/shot-tablet.mjs`)

- `1024x768` (landscape tablet): desktop 3-column layout, clean — nothing cramped.
- `900x700` (the 861–1023 band): desktop layout **crams** — brand wraps to two
  lines, right-hand speed buttons clip off, canvas squeezed by palette(176) +
  sidebar(232) = ~408px of chrome.
- `768x1024`, `834x1112` (portrait tablets): fall into the **phone** UI — tools in
  a bottom strip, panels hidden in a drawer — under-using the tall screen.

## Decisions

- **D1. Three tiers, disambiguated by height.** Width alone can't tell a portrait
  tablet (768×1024, tall) from a landscape phone (844×390, wide but short). Use
  height as the discriminator.
  - Phone: `max-width: 767px`, OR `(max-width: 1023px) and (max-height: 599px)`.
  - Tablet: `(min-width: 768px) and (max-width: 1023px) and (min-height: 600px)`.
  - Desktop: `min-width: 1024px` (unchanged base).
  - Rationale: landscape phones stay on the phone drawer (no vertical room for
    docked panels); portrait tablets and the cramped 861–1023 desktop band get the
    new roomy tablet layout; 1024+ keeps the proven desktop layout.
- **D2. Top bar wraps on tablet** (reuse the phone approach: stats drop to a
  full-width second row; brand + speed buttons stay on row one). Fixes the brand
  wrap / button clip cram directly. Chosen over shrinking font, which hurts
  legibility on a touch device.
- **D3. Palette stays a docked side column** (not the phone bottom strip) —
  narrowed to 150px so the canvas keeps room. A tablet has the width for a proper
  tool list; the bottom strip is a phone compromise.
- **D4. Right panels stay docked** (always visible), narrowed to 200px — no phone
  drawer. Using the tablet's space to keep SELECTED/TOWER/BULLETIN/GAME in view is
  the whole point of the tier; `#panel-toggle` (☰) is hidden on tablet.
  - Canvas budget at the narrow edge (768px): 768 − 150 − 200 − margins ≈ 400px
    wide, but portrait canvas is very tall and the player pans/zooms — acceptable.
- **D5. Comfortable touch targets.** `pointer: coarse` already grows dialog/editor
  buttons and adds the ✕ tap-halo. Add a min-height to palette rows on tablet so
  tool selection is finger-friendly; keep the retro visual sizing otherwise.
- **D6. Degrade cleanly at the edges.** Because the phone query now stops at
  767px/short screens, the base desktop layout naturally applies across 768–1023
  tall; the tablet block only *tweaks* (topbar wrap, column widths, tap sizes) —
  no new structural HTML, no drawer machinery. Engine stays DOM-free (pure
  CSS + the existing markup).

## Assumptions

- A1. Landscape tablets (≥1024px wide) are well served by the existing desktop
  layout (evidence: 1024×768 is clean), so desktop starts at 1024 and tablet is
  portrait/compact only.
- A2. `min-height: 600px` is the tablet floor; below it (short landscape phones)
  the phone layout is correct. iPad landscape (768px tall) is desktop by width, so
  the 600px floor never strands a real tablet.

## Open questions

- (none blocking) Whether to also grow the top-bar speed buttons on touch is left
  to implementation + playtest; `pointer: coarse` can carry it if wanted.
