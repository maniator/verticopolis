Design decisions locked:
- isSplashUp() backs on getElementById("splash") (the DOM element, AD-1's named source). Initially drafted as registry-backed (hasLiveSplash), reversed to DOM-backed because ~8 test files simulate "splash up" via a raw #splash element and registry-backing would break them all; DOM-backing keeps those green and is equally faithful. To keep hostCommands' guard AND dispatch on ONE answer (preserving #715's round-3 unification), the dispatch now decides via isSplashUp() before calling runSplashAction, so both read the DOM. hasLiveSplash is deleted; splashActions is now a pure action registry. getElementById("splash") appears in exactly one production reader, interactionState.ts (Onboarding creates/removes the element via the splashEl ref, not getElementById).
- isDialogOpen() reads #modal.open directly (crash-safe, matches #715); UI.isModalOpen stays as the modal-element owner's accessor for UI-internal precedence.
- mode(app): crash > splash > (isDialogOpen||hasBlockingModal) > live. Screens-only (AD-2). editorBusy is a predicate (isEditorBusy(app)), never in mode() (AD-7).
- lastAvailabilityKey moves to the module (owned state), gated changed()/commit() pair so "commit only after successful push" (round-1 fix) is preserved. Keyed via a pure changeKey() helper over the command set (a deterministic function of the five sources + editorBusy), behavior-identical to #715.
- DEFER (backlog): the onInteractionChange event-emitter (AD-2 finer surface / seed). hostCommands keeps its poll, already non-pump-gated via #715 (tick runs in frameLoop's early-return branch), so AD-8's stale-subscriber invariant holds without it. Building an emitter would rearchitect #715's just-merged mechanism.
- Guard (Verification): source-text test forbids the raw reads outside interactionState.ts, with writer/owner exceptions (crashScreen, Onboarding, UI defs, frameLoop/updateFlow WRITES only). shownChoice/shownUpdate distinguished read-vs-write by regex.
