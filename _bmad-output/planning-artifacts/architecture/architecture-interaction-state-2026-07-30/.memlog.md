- (constraint) [ADOPTED issue #716] Bar: worth doing ONLY if one module owns all five sources. Owning two adds a sixth reader rather than removing four. A partial consolidation is a regression.
- (decision) AD: One UI-chrome module owns all five interaction-state sources (app.shownChoice main.ts:99, app.shownUpdate main.ts:111, #modal.open, #splash existence, #crash-screen via CRASH_SCREEN_ID). Binds: every reader of 'can the player interact now'. Prevents: two sources disagreeing (the #715 defect: availability push under runFrame early-return on shownChoice||shownUpdate said all-available in the #modal.open refuse-all state). Rule: no code outside the module reads any of the five directly.
- (decision) AD: The module exposes a single precedence-ordered mode query (crash > splash > dialog > live) plus the finer predicates guards branch on, and a change notification (onInteractionChange) firing only when a comparable state key changes. Binds: hostCommands consumers and any future chrome guard. Prevents: re-scattering the reads and re-polling every pump. Rule: guards call the module; the shell subscribes rather than polling.
- (decision) AD [scope narrowing, owner-confirm]: the module owns lastAvailabilityKey ONLY of the three dirty-gates the issue names. paletteScanKey (uiStatus.ts) keys over sim.mode/star/money affordability = simulation content, must not move into a chrome module (would make it read sim, forbidden by the no-lib party ruling). lastUiUpdate (frameLoop) is a wall-clock 6Hz throttle, not a change detector. Prevents: pulling unrelated concerns into the chrome module and violating the sim-untouched constraint. Rule: a shared change-key helper may be extracted for reuse, but data ownership does not move.
- (constraint) Dependency direction: interactionState reads DOM + GameApp chrome fields only; hostCommands and frameLoop depend on interactionState; interactionState depends on neither (no cycle). It never imports from src/engine.
- (constraint) Integration point hostCommands lands with PR #715 (unmerged). This refactor sequences after #715 merges so it is written against final code; fallback is to stack on #715's head and rebase.
